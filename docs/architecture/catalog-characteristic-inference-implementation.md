# Безопасное определение характеристик по каталогу

## Что реализовано

Импорт использует существующий механизм аналогов, но теперь отделяет семейство товара от общих слов и номиналов. Семейный якорь извлекается детерминированно из имени и артикула. Реализация не содержит списка конкретных серий: `AV 10`, `ПРК32`, `АВДТ32`, `ВД1-63` являются тестовыми примерами общего алгоритма.

Совпадение по двум общим словам больше не является самостоятельным основанием. Для допуска кандидата требуется совпавшее семейство, точный артикул или название либо сильное совпадение нескольких уже известных характеристик.

Различия вариантных характеристик не исключают товар из доказательств для других полей. При этом сами вариантные характеристики защищены от автоматического переноса. К ним относятся номинальный ток, диапазон тока, число полюсов, ток утечки и отключающая способность.

## Безопасное автозаполнение

Режим `AutoFill` по-прежнему работает только из выпущенной конфигурации области `производитель + тип`. Дополнительно сервер проверяет, разрешено ли автоматическое заполнение для конкретной характеристики. Ошибочная настройка `AutoFill` для вариантного параметра не приводит к записи значения.

Приоритеты существующего импорта сохранены:

1. ручное значение;
2. корректное значение Excel;
3. строгое распознавание из названия;
4. ранее подтверждённое решение;
5. разрешённое заполнение по аналогии.

Аналогия заполняет только пустое поле. Невалидное явное значение Excel не маскируется аналогом.

## Происхождение

Для значения `CatalogAnalogy` в JSON строки сохраняются:

- идентификатор и версия конфигурации;
- хэш конфигурации;
- идентификатор и время снимка каталога;
- семейный якорь;
- количество, доля и идентификаторы поддерживающих товаров.

Схема существующих таблиц не менялась, поэтому новая миграция не требуется.

Версия снимка доказательства повышена до `catalog-analogy-v3`. Решения, рассчитанные старым алгоритмом, не считаются тем же основанием после перехода на семейный отбор.

Принятое значение по аналогии не становится учебным примером автоматически. Существующая защита финализации обратной связи сохранена, что предотвращает самоподтверждающийся цикл.

## Интерфейс

В поиске аналогов показываются совпавшее семейство, режим характеристики и возможность безопасного автозаполнения. Для вариантного параметра отображается причина запрета.

Поиск также возвращает ограниченную диагностическую выборку исключённых кандидатов. Для каждого видны товар, найденные обозначения и причина: архив, текущий товар, другая область либо отсутствие семейного/сильного основания. Полный объём исключений показывается отдельным счётчиком, а усечение выборки отмечается явно.

В редакторе строки рядом с заполненной характеристикой можно раскрыть источник. Для аналогии показываются семейство, поддержка, версия настройки и снимок каталога.

При повторном анализе ранее сохранённые значения с источником `CatalogAnalogy` сначала исключаются из строки и рассчитываются заново по действующей конфигурации и новому снимку каталога. Ручные значения и значения Excel не удаляются. Если строгое распознавание или текущие аналоги больше не подтверждают значение, оно не переносится дальше, а строка получает предупреждение `characteristic.analogy_stale` с понятным текстом для пользователя.

В рабочем пространстве обучения вариантные характеристики нельзя перевести в `AutoFill`. Для стабильных характеристик сохранён защищённый путь: черновик, оценка и явный выпуск.

На уровне пакета добавлена сводка и серверная фильтрация по пяти состояниям:

- есть строгие значения;
- заполнено по аналогам;
- ожидает подтверждения;
- заблокировано конфликтом;
- остались обязательные пустые значения.

Состояния могут пересекаться: например, одна строка может содержать распознанный из названия номинал и заполненную по аналогам стабильную характеристику. Интерфейс прямо сообщает об этом и не складывает такие счётчики в фиктивный общий итог.

## Снимок на пакет

При анализе пакет больше не загружает конфигурацию и каталог кандидатов для каждой строки. Для каждой области `производитель + тип` один раз фиксируются действующая конфигурация и ограниченный снимок кандидатов. Все строки области оцениваются относительно одного и того же снимка.

Это одновременно:

- устраняет отдельный полный запрос каталога на каждую строку;
- делает результат строк одного запуска воспроизводимым;
- гарантирует одинаковые `configurationHash` и `candidateSnapshotId` внутри области;
- сохраняет верхнюю границу пула из действующей конфигурации (не более 10 000, системное значение — 2 000).

## Проверки

- семейные якоря проверены на латинских и кириллических обозначениях, раздельной записи и дефисах;
- совпадение только по общим словам блокируется;
- другой производитель, тип, архивный и текущий товар не допускаются;
- `AutoFill` вариантных характеристик блокируется независимо от настройки;
- стабильная характеристика может пройти `AutoFill` при достаточной поддержке;
- происхождение принятого решения сохраняет снимок и количество оснований;
- 171 unit-тест Core и 60 unit-тестов CatalogImport проходят;
- отдельный тест подтверждает удаление старого аналогового значения, если текущий каталог больше не даёт достаточного основания;
- API собирается в отдельную папку без предупреждений и ошибок;
- TypeScript, ESLint и production-сборка frontend проходят;
- PostgreSQL-сводка и все пять серверных фильтров проверены на локальном смешанном пакете: полученные количества совпали;
- Web integration-тесты собраны, но не запущены: Docker/Testcontainers недоступен в текущей среде.

Обычная выходная папка API во время проверки была занята запущенным локальным процессом. Приложение не останавливалось; сборка выполнена с отдельным каталогом результата.

Для runtime-проверки кратковременно запускался отдельный API на другом порту с той же локальной БД. Миграций не было и они не применялись. Проверочный процесс остановлен; основной локальный API не перезапускался.
