# Этап 7. Рабочее пространство обучения

## Пользовательский путь

В разделе `/catalog/recognition` добавлен вход «Обучение и выпуск знаний». Рабочее пространство находится в `/catalog/recognition/learning`. Сначала выбираются производитель и тип товара. Без полной области запрос обзора не выполняется, нулевые показатели не подставляются.

Вкладки: обзор, мои подтверждения, правила, словарь, мои отчёты, действующая конфигурация. Правила и словарь — независимые ветки; общего состояния Ready нет.

Правила: подготовить точное, одиночное числовое или составное числовое предложение → явно сохранить черновик → выбрать состав и название версии → открыть созданную версию → выбрать собственный пакет → создать сравнительный отчёт → проверить основания и подтвердить включение. Генерация и сохранение черновиков доступны без пакета; проверки на строках и выпуск требуют подходящего пакета. Ничего не генерируется при открытии вкладки.

Словарь: выбрать учебное предложение в нужном состоянии → проверить основания → отредактировать окончательное решение → оценить влияние → просмотреть отчёт → явно одобрить. Используется прежняя форма и защищённые команды. Отклонение не зависит от достаточности оснований. Ручные предложения и администрирование остаются отдельными инструментами.

На вкладке действующей конфигурации видны версия и sequence; доступны проверка её учебных оснований, переход к одобренным словарным предложениям, отдельное отключение правил с причиной и подтверждением и новое распознавание текущей конфигурацией. Пересмотр оснований не отключает знания автоматически. Возврат к прежней версии требует новой оценки.

## Навигация и повторное использование

`manufacturerId`, `productTypeId`, `branch`, `section`, `id`, `page`, `status`, `batchId`, `batchPage` находятся в URL. Смена области удаляет выбранные объекты прежней области. Ключи запросов включают пользователя, область, раздел и фильтры; ответы прежней области не подменяют новую. Прямые ссылки на выбранные объекты дополнительно проходят серверную проверку принадлежности области и доступности.

Ссылки на импорт передают локальный `learningReturn`, а экран импорта возвращает к выбранной области и объекту. Список импортов сохраняет этот контекст в ссылках на пакеты и даёт возврат. Ссылка из сравнительного отчёта на контрольные примеры содержит область отчёта. Выбранный пример показывается вместе с его действиями даже вне текущей страницы списка.

Переиспользованы генераторы/списки/сохранение трёх видов черновиков, создание версии, панель активации, общая панель оценки, управление примерами и происхождением. Карточка словарного предложения выделена из Next-страницы в переиспользуемый модуль; старый маршрут экспортирует тот же компонент. Вторых реализаций одобрения и переключения нет.

Успехи и ошибки операций обновляют проекции и готовность. Панель переключения, выполняющая запросы без React Query mutation, явно инвалидирует обзор и готовность. Ответ 409 не показывается как успех. Подтверждение отключения сбрасывается при смене sequence.

## API и права

`GET /api/catalog/recognition/learning-workspace/{section}`:

- обязательные `manufacturerId`, `productTypeId` — существующие непустые GUID;
- `section`: `overview`, `examples`, `literal`, `integer`, `multi`, `versions`, `suggestions`, `batches`, `ruleReports`, `dictionaryReports`;
- `page`: 1–10000, размер страницы фиксирован — 20;
- `id`: адресный выбор объекта, 404 для недоступного объекта или объекта другой области;
- `parentId`: версия для списка ruleReports, предложение для dictionaryReports;
- `status`: All/Pending/Approved/Rejected для предложений.

Новые API проверяют активность пользователя и эффективное DictionariesManage, включая запрещающий override. Ответы помечены `private, no-store`. Примеры и отчёты ограничены текущим автором; пакеты — владельцем. Область не заменяет авторизацию. Общие черновики, версии и предложения доступны рецензентам по прежней модели прав. Новый список предложений не выдаёт тексты исходных evidence-наблюдений других пользователей.

Каждый запрос читает ограниченную проекцию в RepeatableRead без mutation gate. `asOfUtc` отмечает время формирования снимка; вкладки и детали не обещают единого атомарного состояния между запросами. Серверная пагинация применяется до материализации, totalCount вычисляется сервером. Нет загрузки всех страниц в браузер, N+1 вызовов evaluator или загрузки больших снимков отчётов ради списка.

Пакеты выбираются по владельцу и фактическому числу строк 1–2000. Смешанные пакеты не исключаются по типу/производителю заголовка. Отдельных ограничений статуса сверх прежнего сервиса не введено; окончательная применимость и допуск проверяются существующей оценкой и переключателем.

## Значение показателей и состояний

«Мои подтверждения для правил» — неотозванные примеры пользователя с существующим неисключённым источником и IsEvaluationOnly=false. «Только контроль правил» — аналогичная выборка с IsEvaluationOnly=true. «Отозванные» — все собственные отозванные подтверждения области. «Исключённые источники» — различные исключённые SourceFeedbackId собственных примеров. Последние два показателя могут пересекаться; их нельзя суммировать как независимые стадии. Назначение контроля правил не исключает Feedback из обучения словаря.

Черновики, версии и состояния предложений считаются по всей доступной общей области, а не по текущей странице. Счётчиков чужой приватной разметки/отчётов нет. Наличие примеров не гарантирует генерацию правила или независимость контроля.

Списки отчётов показывают сохранение и дату с явной отметкой «актуальность не проверена». Сохранённые метрики и текущий допуск открываются только у выбранного отчёта через прежний сервис. Поддерживаются недостаточность контроля, провал, устаревание, актуальный допуск и историческое воспроизведение. Недоступность API не превращается в нулевой счётчик. Загруженные сведения не объявляются доказательством актуальности всех знаний области.

После удаления исходного импорта отчёт остаётся в собственном списке и открывается. Отмечается отсутствие пакета; для нового выпуска пользователь выбирает другой пакет и создаёт новую оценку. Словарный выпуск не требует фиктивного пакета.

## Хранение и развёртывание

Новых таблиц, миграций, очередей, фоновых процессов и флагов готовности в этапе 7 нет. Используются существующие связи и индексы; нагрузочная проверка на промышленном объёме не проводилась. История и сроки хранения не изменены.

Обновить API и frontend. Этап требует схемы предыдущих этапов. Если их миграции ещё не применены, учитывать автоматический MigrateAsync при запуске штатного API и порядок согласованного обновления, описанный в документах этапов 5–6. В ходе этой реализации рабочая БД не использовалась, миграции к ней не применялись. API для тестирования запускался через изолированный Kestrel-host тестового проекта, без штатного Program.cs и рабочего seeder.

## Проверки

Сборка API в конфигурации Evaluation прошла без ошибок и предупреждений. Финальная production-сборка frontend, отдельная проверка TypeScript и ESLint прошли. Проверка diff не выявила ошибок пробелов.

Пройдено 40 unit и 75 целевых интеграционных тестов, включая 9 новых проверок рабочего пространства. PostgreSQL 18 Testcontainers со штатными миграциями; реальные HTTP-контроллеры. Проверены пагинация 23 версий, общие и собственные выборки, прямые ссылки другой области/пользователя, блокировка и override, отсутствие генерации/записей при GET, состояния после выпуска/отзыва/исключения, история после cleanup и некорректные параметры.

Для браузерной проверки добавлен opt-in `WorkspaceBrowserHarness`: при отсутствии `LEARNING_BROWSER_SESSION_FILE` пропускается; с заданным абсолютным путём создаёт временную БД и две тестовые области, записывает адрес сервера/ID в файл и держит host до удаления этого файла или 30 минут. Тестовая аутентификация используется только в тестовом проекте; производственное приложение не изменено. Фоновое обучение/cleanup отключены в host. Запуск harness не считается функциональным тестом интерфейса.

Во встроенном браузере пройден путь правил: генерация точного предложения, сохранение черновика, выбор состава, создание версии, оценка с улучшением без регрессий, проверка оснований, подтверждённое включение и распознавание нового названия выпущенной версией. Пройден словарный путь: выбор предложения, оценка (2 улучшения без регрессий), подтверждённое одобрение, созданный термин и связанный исторический отчёт. Проверены восстановление области и вкладки при перезагрузке, очистка области без показа прежних данных и возврат браузером к выбранному предложению. Это интерактивная браузерная проверка двух основных путей, не полный автоматизированный E2E-набор. Временные страницы входа удалены, тестовый host остановлен.

При тестовом restore использован разовый `-p:NuGetAudit=false` из-за существующего advisory SSH.NET; постоянные настройки аудита не менялись.
