# Реализация жизненного цикла примеров — 2026-09-22

## Использование

На `/catalog/recognition` появился раздел «Обучающие примеры». Он показывает собственные подтверждения пользователя с фильтрами по производителю, типу, характеристике и состоянию. Страницы по 25 записей выбираются на сервере. Карточки содержат сохранённое имя, фрагмент, значение, область, дату и историю отзыва. Отсутствующий импорт не мешает управлению примером.

«Отозвать подтверждение примера» требует причину. Новые выборки для черновиков и экспорт подтверждённых примеров исключают отозванную запись. Проверенный feedback, накопленные кандидаты, исторические отчёты и действующие версии правил не изменяются. Старые выгрузки также не переписываются. Повторное подтверждение создаёт новый ExampleId с сохранением старой истории.

## API и права

- `GET /api/catalog/recognition/training-examples`: фильтры ManufacturerId, ProductTypeId, CharacteristicDefinitionId, Status (active/revoked/all), Page.
- `GET /api/catalog/recognition/training-examples/{id}`: карточка.
- `POST /api/catalog/recognition/training-examples/{id}/revoke`: JSON `{ "reason": "..." }`, до 1000 символов.
- `GET /api/catalog/recognition/training-examples/export`: область задаётся теми же тремя идентификаторами; выгружаются все активные записи, независимо от Page/Status.

Все операции требуют активную учётную запись и DictionariesManage. Управление и новый экспорт ограничены ConfirmedByUserId текущего пользователя. Чужие идентификаторы не раскрываются. Нового административного полномочия не введено. Внутренний TrainingSampleReader остаётся общим для области, без фильтра владельца.

Старый путь отзыва из импорта проверяет связь с пакетом/строкой и делегирует общей операции. Старый запрос без body остаётся допустимым; причина отмечается как `legacy-api: причина не передана старым клиентом`. Обновлённый интерфейс передаёт введённую причину. Старые записи миграция не заполняет выдуманными причинами.

## Источники

RecognitionLearningSelection.ReviewedFeedback сохраняет условия Finalized + IsTrainingEligible + cutoff для агрегатора и старого экспорта. ConfirmedExamples + InScope применяются для текущей учебной выборки, нового экспорта и списка активных примеров.

Новый формат `confirmed-examples-v1` — JSONL: первая строка recordType=metadata, остальные recordType=example. Метаданные содержат SelectionAsOfUtc, область, ограничение текущим владельцем и единицы координат UTF-16 code units. Записи содержат ExampleId, SourceFeedbackId, область, ProductName, RawValue, NormalizedValue, SpanStart/SpanLength и ConfirmedAtUtc. Подтверждённая разметка не подменяет SuggestedSpan старого формата.

Выгрузка формируется потоково во временный файл в RepeatableRead-транзакции, после чего файл передаётся клиенту и удаляется при закрытии. Снимок устанавливается SQL-чтением до обхода записей. Это действующая разметка на начало выборки, не восстановление состояния по историческому cutoff. Формат не совместим со старым bundle-валидатором; bundle/split для нового источника не добавлены.

## Хранение и очистка

Миграция `20260922062140_AddTrainingExampleRevocationReason` добавляет nullable `revocation_reason` в существующую таблицу. Отзыв — условный UPDATE по владельцу и `revoked_at_utc IS NULL`: конкурентные запросы сохраняют первое решение целиком.

Интеграционная проверка обнаружила старый конфликт удаления пакета: независимые FK SET NULL могли сначала обнулить ImportBatchId, оставив ImportRowId, что нарушало `ck_catalog_recognition_feedback_import_links`. В ту же миграцию включён BEFORE DELETE trigger на catalog_import_batches: он предварительно отсоединяет ссылки на строки в feedback. Затем штатные FK удаляют ссылки на пакет. Это работает и для cleanup, и для иных удалений пакета; feedback и TrainingExamples сохраняются. Новых таблиц нет. Миграция проверяется только в изолированной тестовой БД; к рабочей БД в этой задаче не применяется.

Literal/integer recheck сравнивают состав ExampleId с текущей выборкой; multi-integer проверяет наличие подтверждений выбранных имён и состав оснований. Activation validator сохраняет обязательные training checks. История оснований не удаляется, автоматического отключения действующей версии нет.

## Проверки и ограничения

Результаты запусков записываются в архитектурной карте после завершения проверки. Проверки используют временный PostgreSQL-контейнер с настоящими миграциями. Для restore тестового проекта потребовался локальный `-p:NuGetAudit=false` из-за ранее существующих NU1903 SSH.NET; постоянные настройки аудита и версии зависимостей не изменялись.

Браузерный E2E не выполнялся. Новая страница проверяется сборкой, TypeScript и ESLint; серверные сценарии — интеграционными проверками. Следующие этапы (глобальное исключение feedback, оценка качества и реорганизация таблиц) не реализованы.
