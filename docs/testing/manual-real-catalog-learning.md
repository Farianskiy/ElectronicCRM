# Проверка определения типов и характеристик на реальном каталоге

Тестовые файлы находятся в `F:\Projects\ElectronicCRM\outputs\real-catalog-learning-test`.

Во всех импортируемых файлах есть только исходные поля: наименование, артикул, производитель, цена и остаток. Колонок типа товара и характеристик нет.

## Порядок

1. Перезапустить API, чтобы загрузилась актуальная реализация определения типов.
2. Загрузить `01_Модульные_автоматы_без_характеристик.xlsx` в режиме добавления новых товаров.
3. Открыть строки и убедиться, что тип определён автоматически. Для первой строки должны быть распознаны как минимум `1P`, `13 A` и `10 кА`.
4. В редакторе первой строки нажать `Найти аналоги`. Система должна найти товары EKF семейства `AV 10` и предложить согласованные отсутствующие характеристики. Различие номинального тока не должно исключать эти товары из доказательств для серии, теплового расцепителя и характеристики срабатывания.
5. Загрузить `02_Мотор_автоматы_без_характеристик.xlsx`. Если семейство `ПРК32` ещё не используется для автоматического типа, назначить общий тип `Мотор-автомат`, проверить распознавание и применить пакет в каталог.
6. Загрузить и применить `03_Дифференциальные_автоматы_первичная_база.xlsx`, вручную назначив общий тип `Дифференциальный автомат`, если он не определён автоматически.
7. Загрузить и применить `04_УЗО_первичная_база.xlsx`, вручную назначив общий тип `УЗО`, если он не определён автоматически.
8. Загрузить `05_Смешанный_файл_без_типа_и_характеристик.xlsx`. Оставить режим `Определять по строкам` и не назначать общий тип.
9. Загрузить `06_Новые_номиналы_известных_серий.xlsx`. Не назначать общий тип и не добавлять колонки характеристик. Открыть по одной строке каждого семейства и проверить раскрывающийся источник значений.
10. Загрузить `07_Похожие_слова_другие_серии.xlsx`. Не назначать общий тип. Общие слова `автомат`, `выключатель`, `УЗО` и похожие номиналы не должны давать семейное основание для автоматического переноса характеристик.

## Ожидаемый результат смешанного файла

- `AV 10 ...` — модульный автомат;
- `ПРК32 ...` — мотор-автомат;
- `АВДТ32 ...` — дифференциальный автомат;
- `ВД1-63 ...` — УЗО.

Все восемь строк должны получить тип без ручного выбора. Характеристики, явно записанные в названии, должны быть распознаны базовыми правилами. Отсутствующие значения могут быть предложены только при достаточном числе согласованных аналогов.

## Ожидаемый результат файлов 06 и 07

Файл 06 содержит новые номиналы уже известных серий `AV 10`, `ПРК32`, `АВДТ32` и `ВД1-63`.

- тип определяется по известному семейству;
- ток, число полюсов, диапазон, ток утечки и отключающая способность берутся из текущего названия;
- эти параметры не копируются с существующего товара с другим номиналом;
- стабильная отсутствующая характеристика может быть предложена, а при выпущенном режиме `AutoFill` — заполнена;
- у значения по аналогии видны семейство, поддержка, версия настройки и снимок каталога.

Файл 07 содержит те же общие слова и похожие номиналы, но другие обозначения серий: `XZ 20`, `QF 32`, `MTR40`, `PKZ50`, `DX40`, `RCBO50`, `RCD40`, `RCCB80`.

- существующие семейства `AV 10`, `ПРК32`, `АВДТ32`, `ВД1-63` не должны использоваться как основание;
- совпадение только по словам типа товара или номиналам не должно включать автозаполнение;
- строгие значения, присутствующие в названии, продолжают распознаваться обычным механизмом;
- отсутствие семейного основания показывается как отсутствие надёжных аналогов, а не маскируется случайным предложением.

После анализа каждого файла откройте `Техническая сводка` → `Как заполнены характеристики`.

- `Заполнено по аналогам` показывает только строки, где выпущенная конфигурация действительно применила `AutoFill`;
- нажатие карточки фильтрует весь пакет, а не только открытую страницу;
- для файла 06 в раскрытом источнике значения должны быть видны семейство, поддержка, версия настройки и снимок каталога;
- вариантные параметры файла 06 не должны иметь источник `Заполнено по похожим товарам`;
- для файла 07 карточка `Заполнено по аналогам` должна оставаться пустой, если в каталоге нет настоящих товаров соответствующих новых серий.

## Проверка повторного анализа и устаревшего основания

1. В файле 06 найдите строку, в которой стабильная характеристика получила источник `похожие товары каталога`.
2. Раскройте источник и запишите семейство, версию настройки и идентификатор снимка каталога.
3. Измените учебное основание безопасным способом: исключите поддерживающие подтверждения либо переведите характеристику действующей области из `AutoFill` в `Suggest` через новый черновик, оценку и выпуск.
4. Вернитесь в импорт и запустите повторный анализ пакета.
5. Убедитесь, что старое значение не осталось только потому, что было сохранено раньше.
6. Если текущее основание всё ещё достаточно, значение должно быть рассчитано заново и получить актуальный снимок. Если основания больше нет, поле должно очиститься, а в строке появится предупреждение `Значение по аналогам больше не подтверждено`.
7. Убедитесь, что значения из Excel и ручные исправления в этой же строке сохранились.

## Зафиксированный исходный результат

До исправления точных названий типов смешанный файл дал такой результат:

- модульные автоматы: правильно, 99%;
- мотор-автоматы: ошибочно предложен модульный автомат, 90%;
- дифференциальные автоматы: ошибочно предложен модульный автомат, 90%;
- УЗО: тип не определён.

Причина состояла в том, что общий словарный термин `автомат` участвовал в выборе, а канонические названия типов не входили в индекс. Реализация исправлена: точное каноническое название типа стало сильным основанием. Отдельно разрешено использовать близкие товары с отличающимся номинальным током или диапазоном тока как доказательства для других характеристик.

Определение по каталогу выполняется только при достаточном основании: минимум три близких товара, не менее 80% согласия по типу и отсутствие равного конкурирующего варианта. Кандидаты каталога загружаются один раз для каждого производителя на весь анализ файла.
